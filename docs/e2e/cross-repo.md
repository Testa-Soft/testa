# Cross-repo live e2e — testa-platform PRD-006 × crobot Analytics V2 (X0)

The scoreboard for the Definition of Done of both PRDs. Every check runs
against the **real local processes of both systems**; nothing at the boundary
is mocked. A check is `pass`, `fail`, or `pending-<package>` (the feature isn't
built yet — route 404/501, class / table / UI missing). Pending is never a pass.

## Run it

```sh
# from a testa-platform checkout with `pnpm install` done
pnpm e2e:cross                                  # up → all layers → report → down
pnpm e2e:cross --keep-up                        # leave everything running (UI clicking, debugging)
pnpm e2e:cross --down                           # stop a --keep-up stack
pnpm e2e:cross --only contract,sync.pull-rows   # layers / check ids (+ their dependencies)
pnpm e2e:cross --strict                         # pending counts as failure (X1 acceptance)
pnpm e2e:cross --platform-dir ~/projects/testa-platform/.worktrees/p6 \
               --crobot-dir   ~/projects/crobot/.worktrees/cint
bun test scripts/e2e/cross                      # harness self-tests (golden → derivation)
```

Report: `node_modules/.cache/e2e-cross/report.{md,json}`; process logs in
`node_modules/.cache/e2e-cross/logs/`; UI screenshots in `node_modules/.cache/e2e-cross/screenshots/`. Exit 1 on any
failure (or pending with `--strict`).

Prerequisites (checked, fails loudly): `bun`, Docker with `tp-clickhouse`,
`tp-redis`, `crb-mysql`, `crb-redis`, network `crb-net`, image `crobot-crb-php`;
`pnpm install` in the platform dir; `composer install`, `npm ci && npm run build`
in the crobot dir (inside `crb-php`, crobot PRD §10a).

## Topology

| Piece | Where | Isolation |
|---|---|---|
| ClickHouse | `tp-clickhouse` :8123 | database `prd006_x0`, dropped + re-migrated every run |
| Redis (platform) | `tp-redis` :6380 | DB index **9** (reserved for X0) + stream `prd006:x0:events` |
| Collector API | `bun` on the host, **:8091** (`--platform-dir`) | own env; 8090 (tp-collector) untouched |
| Consumer, modeler | `bun` on the host | same env; modeler started when `src/modeler/main.ts` exists |
| Edge | `wrangler dev` :8792 (local only) | → collector :8091, own HMAC secret |
| crobot web | container `crb-e2e-web` (image `crobot-crb-php`, `crb-net`), `artisan serve` → host **:8188** | compose project `crobot-e2e`; mounts the crobot repo, workdir = `--crobot-dir` |
| crobot worker | container `crb-e2e-worker` (`queue:work redis`) | same env |
| crobot MySQL | `crb-mysql` | database **`crobot_e2e`** only (migrate:fresh + `E2EAnalyticsSeeder` each run; the seeder and command refuse any other DB) |
| crobot Redis | `crb-redis` | DB 11/12, prefix `crobot_e2e_` |

Env handed to crobot (`docker/e2e/e2e.sh` writes `.generated/e2e.env`, git-ignored):
`TESTA_ANALYTICS_MOCK=false`, `TESTA_COLLECTOR_API_URL=http://host.docker.internal:8091`,
`TESTA_METRICS_TOKEN`, `TESTA_ANALYTICS_WEBHOOK_SECRET`, `TESTA_COLLECTOR_TOKEN`
(throwaway values generated by the harness, `node_modules/.cache/e2e-cross/secrets.json`). Every
other key of the worktree `.env` that isn't infrastructure is **blanked**, so no
real integration (Slack, Stripe, Klaviyo, Apify, CF purge, CRO agent, Google)
can fire. The platform gets the same service token / webhook secret and
`CROBOT_WEBHOOK_URL=http://localhost:8188`.

Seed (crobot ↔ platform ids): project **42** (uuid `e2e00000-0000-4000-8000-000000000042`);
experiments by `identifier` **1717** (F1, variations 100/101), **1802** (200/201),
**1903** (F3, 100/101/102), **1900** (v1). crobot primary keys deliberately differ
(experiments 5001–5004, variations 6001–6009) so id/identifier mix-ups fail.
User `e2e-analytics@testa.local` / `e2e-analytics-local-only` (local only).

Data enters only through the real ingest path: HMAC `POST /_ingest` → Redis →
consumer → `events_buffer` → `events` (F1 from the golden raw rows, F3 generated
exactly per the validation doc), plus one pixel-shaped event through the edge.

## Overlap with P5 (`scripts/e2e/prd006`)

- `scripts/e2e/cross/shared/f1-wire.ts` (F1 golden raw rows → wire events),
  `shared/f3-wire.ts` (F3 generator) and `shared/ingest-client.ts` (HMAC batches +
  flush wait) are written to be imported by P5's `fixtures/` and `ingest.ts`.
- Both harnesses must not run at the same time on the same ports: P5/P6 use
  8090 by plan, X0 uses 8091 / 8792 / 8188 and its own CH database and Redis DB.
- Spec conflict found: 006-validation.md says health `purchase` events control **2**
  (v1 incl. the reload duplicate), the golden `f1/modeled/health.json` says **1**.
  X0 asserts only what both agree on; the orchestrator should settle it.
