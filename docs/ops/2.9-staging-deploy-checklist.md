## Step 1 — Create KV namespaces (human, CF dashboard or CLI)

```sh
wrangler kv namespace create KV_PROJECT_CONFIG --env staging
wrangler kv namespace create KV_INTEGRATION_BUNDLES --env staging
```

Record the returned IDs and place them in `wrangler.toml` under `[env.staging]`:

```toml
[env.staging]
name = "testa-edge-staging"
vars = { ENVIRONMENT = "staging" }

[[env.staging.kv_namespaces]]
binding = "KV_PROJECT_CONFIG"
id = "<real-id-from-wrangler>"
preview_id = "<preview-id-from-wrangler>"

[[env.staging.kv_namespaces]]
binding = "KV_INTEGRATION_BUNDLES"
id = "<real-id-from-wrangler>"
preview_id = "<preview-id-from-wrangler>"

[[env.staging.durable_objects.bindings]]
name = "BATCH_BUFFER"
class_name = "BatchBuffer"
```

**Do NOT commit real KV IDs to this repo.** Store them in the CF dashboard and reference them from `wrangler.toml` only in a non-committed local override, or accept that the staging IDs are non-sensitive (they are not secrets).

---

## Step 2 — Set secrets (human, wrangler CLI)

```sh
wrangler secret put INGEST_SHARED_SECRET --env staging
wrangler secret put INGEST_ORIGIN_URL --env staging
wrangler secret put COOKIE_FALLBACK_DOMAIN --env staging
wrangler secret put VISITOR_ID_SALT --env staging
```

Values:
- `INGEST_SHARED_SECRET` — a 32+ byte random hex string, **shared with the collector's `INGEST_SHARED_SECRET` env var**.
- `INGEST_ORIGIN_URL` — the collector's staging base URL, e.g. `https://collector-staging.testa.internal`.
- `COOKIE_FALLBACK_DOMAIN` — shared-domain fallback, e.g. `.testa.com` (or `.testa-staging.com` for isolation).
- `VISITOR_ID_SALT` — a random 16+ byte hex string (daily rotation is a Phase 6+ enhancement; use a static value for staging).

---

## Step 3 — Seed KV data (human)

Before the first request can be served, the KV namespace `KV_INTEGRATION_BUNDLES` needs the legacy bundle entries that crobot currently serves:

```sh
# Upload the 3.4 and 3.6 integration bundles (content from crobot)
wrangler kv key put "integration_bundle:3.4" \
  --path ./crobot-export/integration_3.4.js \
  --namespace-id <KV_INTEGRATION_BUNDLES_ID> \
  --env staging

wrangler kv key put "integration_bundle:3.6" \
  --path ./crobot-export/integration_3.6.js \
  --namespace-id <KV_INTEGRATION_BUNDLES_ID> \
  --env staging
```

`KV_PROJECT_CONFIG` is seeded by the crobot config-publish side (`N.8`). No manual seeding needed there — the next `GenerateProjectScriptHandler` run will populate it.

wrangler deploy --env staging

## Step 5 — Smoke test

```sh
# 1. Health-ish (edge worker doesn't have a /health route, so test the pixel serve)
curl -si https://testa-edge-staging.workers.dev/projects/<slug>.js | head -5

# 2. Track event (replace SHARED_SECRET with the value you set)
BODY='{"signed_at":'$(date +%s000)',"events":[{"event_id":"smoke-01","event_name":"page_view","client_ts":0,"server_ts":0,"project_id":1,"visitor_id":"smoke-visitor","session_id":"smoke-session","url":"https://example.com","consent_state":"granted","tracker_version":"4.0.0-smoke","viewport_w":1280,"viewport_h":720,"country":"US"}]}'
SIG=$(echo -n "$BODY" | openssl dgst -sha256 -hmac "$SHARED_SECRET" -hex | sed 's/.*= //')
curl -si -X POST https://testa-edge-staging.workers.dev/track \
  -H "Content-Type: application/json" \
  -H "x-edge-signature: $SIG" \
  -d "$BODY"

# Expected: 204 No Content from the edge, event appears in collector logs
```
