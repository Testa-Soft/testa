## Goal

Replace the per-experiment cookie explosion (3.3.3 parity: `_testa_exp_<id>`,
`_testa_ses_<id>`, `_testa_excl_<id>`, `_testa_user_<id>` — 3–4 cookies × N
experiments) with a **single consolidated cookie** holding a compact map of all
experiment state. Deliberately supersedes the layout shipped in 3.3 (parity was
faithful; the per-experiment layout is a scaling bug we don't want to keep).

## Context

At 20 experiments the current layout sets 60+ cookies. Two concrete failures:
- Browsers cap cookies per domain (~50–180). Past ~15–40 tests, cookies get
  **evicted** → assignments silently lost → visitors flip buckets mid-test →
  **SRM break**.
- Every cookie rides every HTTP request → header bloat, and with first-party
  proxying that bloat hits the customer's own origin too.

Decision (2026-07-08 grill, [[decision_experiment_storage_model]]):
- **Keep the data** for `exp` (assignment), `excl` (exclusion verdict), `ses`
  (session window). Exclusion is NOT derivable — it's a point-in-time targeting
  decision against ephemeral inputs (landing UTM/referrer) AND/OR the traffic
  allocation roll; both must persist.
- **Drop `_testa_user_*`** entirely — lead-sent dedup is obsolete (collector
  dedups by `event_id` / query-time).
- **Bucketing stays derivable** (`xxhash(visitor_id:experiment_id)`); only
  eligibility/exclusion + the resulting assignment persist.

## Acceptance criteria

- One cookie `_testa_exp` holds all experiment state as a **compact positional
  string**, cookie-safe with NO base64:
  - Format: `expId.variation.excluded.sessionExp` per experiment, `~` between
    experiments, e.g. `101.2.0.1720450000~102.1.1.1720450500`.
  - Separators drawn only from the URL-unreserved set (`A–Z a–z 0–9 . _ ~ -`)
    so the value needs no further encoding.
  - ~15 bytes/experiment → 20 tests ≈ 300 bytes, well under the 4 KB cap.
- `store.ts` exposes read/write/upsert over this packed value: `readStore()`,
  `getExperiment(id)`, `setExperiment(id, {variation, excluded, sessionExp})`,
  `serialize()` — all immutable (return new state, never mutate in place).
- Migration/read-compat: on read, if the legacy per-experiment cookies exist and
  the consolidated cookie doesn't, fold them into the consolidated cookie once,
  then stop writing the legacy ones. (Don't strand mid-experiment visitors.)
- `_testa_uuid` remains its own first-party cookie (server-visible identity).
- NO base64 in the default path. If value opacity is ever wanted, base64url is a
  cosmetic wrapper only — document that it is NOT tamper-resistance (an HMAC
  signature would be, and is out of scope here).

## Implementation notes

- Parse defensively: a malformed/truncated cookie value must degrade to "no
  stored state" (fail-open to re-evaluation), never throw.
- Keep `store.ts` free of DOM/`document` coupling where practical — take the raw
  cookie string in / hand the serialized value out, so it unit-tests without a
  browser (mirror how `rules/audience.ts` takes injected context).
- Wire `traffic.ts` / lifecycle to read assignment+exclusion from the store
  instead of per-experiment cookies; write back once per cycle.

## Tests

- Round-trip: serialize → parse → deep-equal for multi-experiment state.
- Compact format is cookie-safe (regex-assert only URL-unreserved chars).
- Malformed value → empty store, no throw.
- Legacy migration: per-experiment cookies present + consolidated absent → folded
  once, consolidated authoritative thereafter.
- Size guard: 20 experiments serialize under ~400 bytes.

## Out of scope

- HMAC-signing the cookie (tamper resistance) — separate task if ever needed.
- Deterministic traffic allocation (replacing `Math.random()` with a hash
  threshold) — related quality upgrade, tracked separately; this task only
  changes storage layout, not the assignment/exclusion logic.
- URL-regex split-URL attribution — see [[decision_experiment_storage_model]];
  its own follow-up.
