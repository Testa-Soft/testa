## Goal

Make the pixel emit a `page_view` event on initial load and on every
meaningful SPA transition, so the collector has the raw material to
sessionize journeys and (later, in crobot) mine funnels. Each page_view
carries an `in_experiment` boolean that drives differential retention
downstream (see 1.8). Crawlers are skipped entirely; humans are capped at
50 page_views/session to bound runaway SPAs.

## Context

Today the pixel emits **no** page_view — the only auto-event is
`experiment_view`. The hard part already exists: `src/runtime/spa.ts`
(task 3.5) provides a debounced, same-URL-deduped `onTransition(url)` hook,
and `runExperimentCycle` re-runs on each transition. `buildPixelEvent`
already assembles `event_id`/`visitor_id`/`session_id`/`url`/`referrer`/
`consent_state`; this task adds the page_view emit + the `in_experiment`
field. The pixel has **no crawler detection today** — that is net-new,
ported from legacy `crobot/.../3.3.3/script.js`.

Depends on: 3.5 (SPA `onTransition`), 3.8 (experiment assignment, so
`in_experiment` is known at emit time).

## Acceptance criteria

- `isCrawler(userAgent: string): boolean` — pure, ported from the 3.3.3
  `script.js` crawler UA check. Lives in `runtime/crawler.ts`.
- page_view fires **once on initial load** and **once per meaningful SPA
  `onTransition`**, reusing the existing debounce + same-URL dedup (no new
  navigation detection).
- page_view is emitted **at the end of `runExperimentCycle`, error-isolated**
  (own try/catch) — it still fires if variation application partially fails.
- page_view fires **even when no experiment matched** → `in_experiment = 0`;
  when ≥1 experiment matched → `in_experiment = 1`.
- **Crawler guard:** if `isCrawler(navigator.userAgent)`, no page_view is
  emitted (ever, for that page/session).
- **Per-session cap:** at most **50** page_views per `session_id`; the 51st+
  are silently skipped. Counter is per-session (resets with the session).
- On a **redirect variation**, do not emit for the page being navigated away
  from — the destination page load fires its own page_view.
- Payload is the existing `PixelEvent` shape + the new `in_experiment` field
  (boolean/`0|1`). No `experiment_id`/`variation_id` on the page_view row —
  attribution is recovered later by joining to `experiment_view`.

## Implementation notes

- Keep `isCrawler` a pure function over a passed-in UA string (don't read
  `navigator` inside it) so it's trivially testable against a UA corpus.
  Port the exact regex/token set from 3.3.3 `script.js` for parity.
- The per-session counter can live alongside the session module (3.3/session
  cookie). A simple in-memory counter keyed by the current `session_id` is
  fine — it does not need to survive reloads (a reload starts a fresh runtime
  and the cap is a runaway-loop guard, not an exact quota).
- `in_experiment` is derived from the assignment result the cycle just
  computed — `1` if any non-excluded experiment matched this page, else `0`.

## Tests

- `isCrawler`: known crawler UAs (Googlebot, bingbot, etc.) → true; common
  browser UAs → false. Parity against the 3.3.3 UA set.
- page_view behavior: load → exactly 1 page_view; N SPA transitions → N
  page_views; same-URL replaceState → deduped (no extra); 50 transitions →
  50 emitted, 51st → 0.
- `in_experiment` = 1 when an experiment matched, 0 when none matched.
- page_view still fires when the experiment cycle throws mid-apply
  (error isolation).
- Crawler UA → 0 page_views.
