## Goal

Prove the read API end-to-end against a live ClickHouse: seed `events` +
`fx_rates`, let the MVs populate, then hit each `/api/v1/metrics/*` route
through the real HTTP handler with a valid `X-Service-Token` and assert the
`MetricSummary` shapes and numbers. Mirrors the Phase-1 integration test
(task 1.7) conventions.

## Acceptance criteria

- `skipIf(!liveCh)` integration suite (same pattern as
  `apps/collector/src/__tests__/integration.test.ts`), run in CI's
  `test-collector` job (live Redis + ClickHouse already provided).
- Seeds a self-contained fixture: one experiment, ≥2 variations, a mix of
  `experiment_view` / `page_view` / `purchase` events across ≥2 currencies,
  plus the matching `fx_rates` rows; unique `project_id`/`experiment_id` per run
  so tests don't collide (per 1.7's hygiene note).
- Asserts, per endpoint:
  - `aov`: `aov`, CI ordering (`ci_low <= aov <= ci_high`), significance shape.
  - `rpv`: RPV uses exposed visitors as denominator; CI stable under the seed.
  - `sessions`: `bounce_rate`/`pages_per_session` match hand-computed values.
  - `funnel`: ordered step counts + `rate_from_prev`.
- auth: a request without `X-Service-Token` → 401; bad params → 400.
- Coverage on `apps/collector/src/metrics/` ≥ 80% lines. (Wire the collector's
  `bun test --coverage` threshold; the collector already reports coverage — see
  task 1.7 for the baseline.)

## Implementation notes

- Force MV visibility deterministically: insert directly into `events` (the MVs
  are populated on insert), then `OPTIMIZE TABLE <mv> FINAL` if a test needs
  merged state before asserting (Summing/Aggregating), rather than sleeping.
- Reads should hit the MVs (or `events` for the significance samples) — match
  whatever 4.3 chose; don't re-implement the queries here.

## Out of scope

- Load/latency benchmarks.
- crobot-side `MetricsProxyController` / Redis cache (lives in the crobot repo).
