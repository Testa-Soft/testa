## Goal

Serve `GET /api/v1/metrics/aov` → `AovSummary`: per-variation average order
value (in `report_currency`) with a 95% CI, plus Welch's t-test significance of
each non-reference variation vs the reference (control).

## Acceptance criteria

- Response is a valid `AovSummary` (`packages/shared-types/src/metric-summary.ts`):
  `experiment_id`, `report_currency`, `from`, `to`, `variations: AovMetric[]`,
  `significance: SignificanceResult[]`.
- Per variation: `aov = revenue / orders` (converted revenue from 4.3),
  `total_revenue`, `orders`, `sample_size = orders`, `ci_low`/`ci_high` from
  `aovConfidenceInterval` (4.2).
- `significance[]`: for each variation vs the reference variation, `welchTTest`
  over per-order values (4.3 `perOrderValues`); `is_significant = p < 0.05`.
- Reference variation selected deterministically: the experiment's control
  (lowest `variation_id` as the v1 heuristic; document it) unless a
  `reference_variation_id` query param overrides.
- `orders = 0` for a variation → `aov = 0`, `ci = [0,0]`, excluded from
  significance (can't test an empty sample) — no divide-by-zero.

## Implementation notes

- Endpoint = `parseMetricRequest` → 4.3 queries → 4.2 stats → assemble summary.
  Keep `aov.ts` thin; the heavy lifting is already in 4.2/4.3.
- Variance for the CI/Welch comes from the per-order sample; if only aggregate
  revenue/orders are available for a variation (no sample pulled), fall back to
  reporting `aov` with a null CI rather than a bogus zero-width interval.

## Tests

- Seeded CH: two variations, known order values → assert `aov`, CI brackets the
  mean, and significance flips as separation grows (drive via fixtures).
- Empty variation → zeros, not NaN; not included in `significance`.
- Currency: orders in EUR + USD with a seeded FX rate → single-currency AOV.

## Out of scope

- RPV / sessions / funnel (their own tasks).
- Caching (crobot's proxy owns the 60s cache).
