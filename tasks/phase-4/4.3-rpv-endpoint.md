## Goal

Implement `GET /api/v1/metrics/rpv` — returns revenue per visitor per variation, converted to `report_currency`, with bootstrap confidence intervals.

## Context

RPV is `total_revenue / unique_visitors`. The numerator comes from `mv_rpv_revenue_daily` (migration 004) and the denominator from `mv_rpv_visitors_daily` (migration 005, which uses `uniqExactState(visitor_id)`). The architecture doc (`02-collector.md`) specifies bootstrap CIs for RPV because, unlike AOV, RPV has a non-normal distribution (many visitors with zero revenue). The `stats.ts` created in task 4.2 is extended here with a `bootstrapCI` function.

`task 4.2` must land before or alongside this task (both modify `metrics/index.ts` and `stats.ts`). If running in parallel, coordinate with the human reviewer.

## Acceptance criteria

- `GET /api/v1/metrics/rpv?experiment_id=42&from=...&to=...&report_currency=USD` returns `RpvSummary` (from `packages/shared-types`).
- Revenue is FX-converted from native currency to `report_currency` using the `fx_rates` CH dictionary (same pattern as AOV).
- `visitors` is the count of unique visitors who triggered `experiment_view` in the date range, from `mv_rpv_visitors_daily` (`uniqExactMerge`).
- `rpv = total_revenue / visitors`.
- `ci_low` and `ci_high` are 95% bootstrap confidence intervals. Bootstrap is computed in TypeScript over the aggregated data (not raw events), using a Poisson-lambda approximation when raw sample data is unavailable (see notes).
- `significance` uses normal approximation on the RPV distribution (two-sided z-test on means); Welch t-test is not appropriate for RPV because the distribution is heavily skewed.
- `experiment_id` required; returns 400 when missing.
- Unit tests for bootstrap CI function with a known distribution.
- Handler tests stub CH and assert response shape.
- `pnpm -r typecheck && pnpm -r test && pnpm lint` pass.

## Implementation notes

### CH query

Two separate queries (or one `JOIN`), then combine in TypeScript:

**Revenue by variation** (from `mv_rpv_revenue_daily`):

```sql
SELECT
    variation_id,
    sum(revenue *
        dictGetOrDefault('fx_rates', 'rate',
          tuple(toDateTime(toStartOfDay(day)), currency, {report_currency:String}),
          1.0)
    ) AS revenue_usd
FROM mv_rpv_revenue_daily
WHERE project_id = {project_id:UInt64}
  AND experiment_id = {experiment_id:UInt64}
  AND day BETWEEN {from:Date} AND {to:Date}
GROUP BY variation_id
```

**Visitors by variation** (from `mv_rpv_visitors_daily`):

```sql
SELECT
    variation_id,
    uniqExactMerge(visitors) AS visitors
FROM mv_rpv_visitors_daily
WHERE project_id = {project_id:UInt64}
  AND experiment_id = {experiment_id:UInt64}
  AND day BETWEEN {from:Date} AND {to:Date}
GROUP BY variation_id
```

Join on `variation_id` in TypeScript (`Map<variation_id, {revenue, visitors}>`).

### Bootstrap CI (Poisson approximation)

We don't store individual visitor-level revenue in the MV — only totals. To bootstrap without raw data, we use the Poisson-lambda approximation:

```
RPV ~ Revenue/Visitors
Bootstrap variance ≈ (1/visitors) * variance_of_per_visitor_revenue
```

Since we don't have individual values, approximate `variance_of_per_visitor_revenue` as:
```
Var(revenue_per_visitor) ≈ (total_revenue / visitors)  // Poisson: Var(X) = λ
```

This yields the standard error:
```
SE = sqrt(rpv / visitors)
95% CI = rpv ± 1.96 * SE
```

This is the Poisson-lambda bootstrap approximation, valid when the revenue-generating process is approximately Poisson. Document the approximation in code comments; a future task can upgrade to exact bootstrap if we add per-visitor revenue storage.

Add `bootstrapCI` to `stats.ts`:

```ts
export interface BootstrapCI {
  ci_low: number;
  ci_high: number;
}

// Poisson-lambda approximation for RPV CI.
// valid_for: RPV where purchases are rare per visitor (λ << 1)
export function rpvBootstrapCI(rpv: number, visitors: number): BootstrapCI {
  if (visitors < 1) return { ci_low: 0, ci_high: 0 };
  const se = Math.sqrt(rpv / visitors);
  return { ci_low: Math.max(0, rpv - 1.96 * se), ci_high: rpv + 1.96 * se };
}
```

### Significance for RPV

Use a z-test on the RPV means (normal approximation valid for large n):

```ts
// z = (rpv1 - rpv2) / sqrt(se1^2 + se2^2)
// p = 2 * (1 - Φ(|z|))  where Φ is the standard normal CDF
```

Add `zTest` to `stats.ts`. Reference: the standard normal CDF approximation from Abramowitz & Stegun (same as used for Welch p-value in task 4.2).

## Tests

- Stub two CH queries (revenue + visitors per variation).
- Assert `rpv = revenue / visitors` for each variation.
- Assert `ci_low < rpv < ci_high`.
- Assert `significance` has one entry.
- Missing `experiment_id` → 400.

`apps/collector/src/metrics/__tests__/stats.test.ts`:

- `rpvBootstrapCI(10, 1000)` → CI within expected range.
- `rpvBootstrapCI(0, 500)` → `{ ci_low: 0, ci_high: 0 }`.
- `zTest` with known z → known p (e.g., z=1.96 → p≈0.05).

## Out of scope

- Exact bootstrap via raw per-visitor revenue resampling (requires storing individual visitor rows — future task).
- Bayesian credible intervals.
- Multi-currency visitors (visitor counts are currency-agnostic).
