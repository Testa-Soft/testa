## Goal

Stand up the collector's **read API** surface: a Hono sub-router mounted at
`/api/v1/metrics/*`, gated by a shared **service token** (the `X-Service-Token`
header crobot's `MetricsProxyController` sends), plus a single validated
query-param parser shared by every metric endpoint. This is the foundation the
per-metric endpoints (4.4–4.7) hang off — it ships with no metric logic yet,
just auth + param validation + wiring, each endpoint returning `501` until its
task lands.

## Context

The write path (PRD-001) and the config API (`/api/v1/config`) already live in
`apps/collector`. The read path is drawn in `diagrams/03-read-path.mmd`: Vue →
Laravel `MetricsProxyController` (60s Redis cache) → `GET /api/v1/metrics/aov`
with `X-Service-Token` → collector → ClickHouse MVs. The config API already
demonstrates a Bearer-token gate (`CONFIG_WRITE_TOKEN`); mirror that pattern for
a **separate** read token so read and write credentials rotate independently.

## Acceptance criteria

- `metricsRouter` (Hono) mounted in `index.ts` under `/api/v1/metrics`.
- `requireServiceToken` middleware: rejects missing/mismatched `X-Service-Token`
  with `401` (constant-time compare); passes through on match. Token read from
  `config.metrics.serviceToken` (new env `METRICS_SERVICE_TOKEN`, required at
  startup like the other secrets).
- `parseMetricRequest(query)` → `MetricRequestBase` or a typed error:
  - `experiment_id` required, positive integer.
  - `from`/`to` optional ISO dates; if both present, `from <= to`; default
    window = last 30 days when omitted (documented).
  - `report_currency` required, ISO-4217 shape (`/^[A-Z]{3}$/`).
  - Returns `400` with a machine-readable `{ error, field }` on any violation.
- The four routes (`/aov`, `/rpv`, `/sessions`, `/funnel`) exist and return
  `501 Not Implemented` with `{ error: 'not_implemented' }` until 4.4–4.7.
- `config.ts` validates `METRICS_SERVICE_TOKEN` present (fail-fast) and exposes
  `config.metrics.serviceToken`.

## Implementation notes

- Reuse the constant-time compare approach from the config-API auth (or
  `ingest/hmac.ts#constantTimeHexEqual` generalized) — do NOT `===` the token.
- Keep `params.ts` pure (query object in → result out) so it unit-tests without
  HTTP. Endpoints call it first thing and early-return on error.
- Do not couple the router to ClickHouse yet — 4.3 introduces the query layer.

## Tests

- auth: missing token → 401; wrong token → 401; correct token → next handler
  runs. Constant-time path exercised (no early length leak assertion needed,
  just behavioural).
- params: valid query parses; each invalid field (`experiment_id` non-int,
  bad currency, `from > to`) → 400 with the offending `field`. Default window
  applied when `from`/`to` omitted.

## Out of scope

- Any SQL / metric computation (4.3–4.7).
- Rate limiting (crobot's 60s proxy cache + service-token trust boundary is the
  v1 control; revisit if the read API is exposed more broadly).
