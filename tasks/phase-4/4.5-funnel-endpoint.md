## Goal

Implement `GET /api/v1/metrics/funnel` — returns the count of unique visitors at each step of a configurable funnel (ordered sequence of event names), per variation. Response matches `FunnelSummary` from `packages/shared-types`.

## Context

The funnel is defined by the caller as an ordered list of `step` query params (e.g., `?step=page_view&step=add_to_cart&step=checkout_start&step=purchase`). The endpoint counts unique visitors who fired each event within the experiment context, then computes `rate_from_prev` (step-over-step drop-off). Default funnel when no steps are provided: `[page_view, add_to_cart, checkout_start, purchase]`.

Unlike AOV/RPV/sessions, the funnel query hits the raw `events` table (not a MV), because the step order is caller-defined and can't be pre-aggregated. For typical query windows (30 days, a few thousand visitors), a direct CH query on `events` with the primary index `(project_id, event_name, client_ts)` is fast enough.

## Acceptance criteria

- `GET /api/v1/metrics/funnel?experiment_id=42&step=page_view&step=add_to_cart&step=purchase` returns `FunnelSummary`.
- Each `FunnelStep` has `event_name`, `count` (unique visitors who fired that event), and `rate_from_prev` (0..1; first step = 1.0).
- Query filters on `project_id`, `experiment_id`, date range, and `is_bot = 0`.
- At least one step is required; returns 400 when `step` is absent or empty.
- Maximum 10 steps; returns 400 when exceeded (prevents unbounded CH fan-out).
- `experiment_id` required; returns 400 when missing.
- Default date range: last 30 days.
- No FX conversion, no significance.
- Unit tests stub CH and assert step counts and `rate_from_prev` formula.
- `pnpm -r typecheck && pnpm -r test && pnpm lint` pass.

## Implementation notes

### CH query

Run one query per funnel step (N queries for N steps) using `uniqExact(visitor_id)` on `events`:

```sql
-- For each step event_name in order:
SELECT uniqExact(visitor_id) AS cnt
FROM events
WHERE project_id    = {project_id:UInt64}
  AND experiment_id = {experiment_id:UInt64}
  AND event_name    = {event_name:String}
  AND client_ts BETWEEN {from:DateTime} AND {to:DateTime}
  AND is_bot = 0
```

Run all N queries in parallel (`Promise.all`). This avoids constructing a complex single-query funnel SQL that would be harder to read and debug. For N ≤ 10, the overhead is negligible.

**Important:** This counts visitors who fired the event *at all* within the date range, not a strict ordered funnel (visitor must have fired step 1 before step 2, etc.). A strict ordered funnel requires a window function or a self-join, which is complex and slow. The "loose funnel" (independent counts per step) is the standard product-analytics default and what crobot's current reports show. Document this in a code comment.

### Response shaping

```ts
const steps: FunnelStep[] = counts.map((count, i) => ({
  event_name: stepNames[i],
  count,
  rate_from_prev: i === 0 ? 1.0 : (counts[i - 1] > 0 ? count / counts[i - 1] : 0),
}));

const variations: FunnelMetric[] = [
  // v1: single variation_id=0 when no variation context (or per-variation if experiment_id provided)
];
```

When `experiment_id` is provided, break down by `variation_id`:

```sql
SELECT variation_id, uniqExact(visitor_id) AS cnt
FROM events
WHERE project_id    = {project_id:UInt64}
  AND experiment_id = {experiment_id:UInt64}
  AND event_name    = {event_name:String}
  AND client_ts BETWEEN {from:DateTime} AND {to:DateTime}
  AND is_bot = 0
GROUP BY variation_id
```

Collect results into `Map<variation_id, count[]>` and build one `FunnelMetric` per variation.

```ts

```

### Query param parsing

```ts
const steps = c.req.queries('step') ?? [];   // Hono multi-value query param
if (steps.length === 0)  return c.json({ error: 'step required' }, 400);
if (steps.length > 10)   return c.json({ error: 'max 10 steps' }, 400);
```

## Tests

`apps/collector/src/metrics/__tests__/funnel.test.ts`:

- Stub N parallel CH queries returning `[{variation_id:100, cnt:500}]` etc.
- Assert `steps[0].rate_from_prev === 1.0`.
- Assert `steps[1].rate_from_prev = steps[1].count / steps[0].count`.
- Zero-guard: if `counts[i-1] === 0`, `rate_from_prev = 0`.
- Missing `step` param → 400.
- More than 10 steps → 400.
- Missing `experiment_id` → 400.

## Out of scope

- Strict ordered funnel (requires visitor-level event sequences — future task).
- Funnel step time constraints (e.g., must convert within 7 days of page_view).
- Funnel significance (no obvious parametric test for drop-off rates in v1).
