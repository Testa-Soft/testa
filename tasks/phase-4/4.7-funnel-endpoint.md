## Goal

Serve `GET /api/v1/metrics/funnel` → `FunnelSummary`: for a caller-supplied
ordered list of `event_name` steps, the per-variation count reaching each step
and the step-to-step conversion rate. This is the read side of PRD-002's funnel
foundation.

## Acceptance criteria

- Request extends the base params with `steps` — an ordered list of event names
  (e.g. `?steps=page_view,add_to_cart,purchase`). Validated in `params.ts`:
  1–8 steps, each a non-empty `event_name`.
- Response is a valid `FunnelSummary`; per variation `steps: FunnelStep[]` with
  `event_name`, `count`, `rate_from_prev` (`count / prev.count`, first step
  `rate_from_prev = 1`).
- **Ordered** funnel: a visitor counts toward step N only if they fired steps
  1..N in `client_ts` order (a later step with no earlier step does not count).
- Counting unit = unique `visitor_id` (document the choice; sessions variant is
  a possible later flag).
- Empty prior step → downstream `count = 0`, `rate_from_prev = 0`, no
  divide-by-zero.

## Implementation notes

- Computed from raw `events` (the daily MVs don't hold sequences). Use
  `windowFunnel(<window>)(client_ts, event_name = s1, …, event_name = sN)` in
  ClickHouse — it's built for exactly this and returns the max consecutive step
  index reached per visitor. Then aggregate `countIf(level >= k)` per step.
  Cite the window size (session-scoped, e.g. 30 min or the experiment window)
  and make it a documented constant.
- Bound-parameterize the step names; never interpolate caller strings into SQL.
- Filter `is_bot = 0`; window by `[from, to]` like the other endpoints.

## Tests (live ClickHouse, `skipIf`)

- Seed a known visitor journey set → assert per-step counts + `rate_from_prev`.
- Out-of-order events: a `purchase` with no preceding `page_view` does not count
  toward the purchase step.
- Single-step funnel → one entry, `rate_from_prev = 1`.
- Hostile step name can't inject (bound params).

## Out of scope

- Path/flow exploration (Sankey) — funnels are fixed ordered steps only.
- Page-path normalization / templating (crobot workstream, per PRD-002).
