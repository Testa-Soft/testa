## Goal

Add a live-infrastructure integration test that seeds ClickHouse with known data and asserts every read-API endpoint returns correct values, including FX conversion and significance fields. Mirrors the Phase 1.7 write-path integration test pattern (`describe.skipIf(!liveStack)`).

## Context

Tasks 4.2–4.5 each include unit tests with stubbed CH. This task validates the full stack: real CH queries hit real materialized views with seeded data. The test is gated on `REDIS_URL` (same flag as 1.7) since the collector integration tests already require `docker-compose` services.

After tasks 4.2–4.5 land, `mv_aov_daily_v2` (migration 011), `mv_rpv_revenue_daily`, `mv_rpv_visitors_daily`, `mv_sessions_daily` are all in place. This test seeds `events_buffer` (which flushes to `events` and populates all MVs), then queries the read API.

## Acceptance criteria

- Integration test file under 250 LOC.
- Gated on `process.env.REDIS_URL` (same `describe.skipIf(!liveStack)` pattern as 1.7).
- Seeds ≥ 2 variations with deterministic data: known visitor counts, purchase counts, revenue, and session/page-view counts.
- Asserts:
  - `/api/v1/metrics/aov` returns correct `aov`, `total_revenue`, and `orders` for each variation.
  - `/api/v1/metrics/rpv` returns correct `rpv` and `visitors`.
  - `/api/v1/metrics/sessions` returns correct `sessions`, `bounce_rate`, `pages_per_session`.
  - `/api/v1/metrics/funnel` with 3 explicit steps returns correct step counts.
  - All endpoints return 401 when `X-Service-Token` is missing.
  - All endpoints return 400 when `experiment_id` is missing.
- Uses a unique `project_id` per run (e.g. `2_000_000 + Date.now() % 1000`) to prevent cross-run pollution.
- Waits for `events_buffer` to flush to `events` (poll `SELECT count() FROM events WHERE project_id = ?` until stable, max 15 s).
- `bun test --testNamePattern=phase-4` on a machine with docker-compose services runs and passes within 30 s.
- `pnpm -r typecheck && pnpm -r test && pnpm lint` pass (tests skip without live services).

## Implementation notes

### Seeding

Insert events directly into `events_buffer` using `insertRows` from `apps/collector/src/db/clickhouse.ts`. Do NOT go through `/_ingest` → Redis → consumer for this test (that chain is already covered by 1.7). Direct insert is faster and sidesteps HMAC/Redis setup.

```ts
import { insertRows, query } from '../../db/clickhouse.ts';

const PROJECT_ID = 2_000_000 + (Date.now() % 1000);
const EXPERIMENT_ID = 9_001;
const VARIATION_CONTROL = 1;
const VARIATION_TREATMENT = 2;

// Seed: 100 experiment_view events per variation, 30 purchases for control (revenue: 50.00 USD each),
//       20 purchases for treatment (revenue: 60.00 USD each),
//       50 page_view events per variation.
```

### Wait for MV flush

```ts
async function waitForCount(table: string, projectId: number, expected: number, timeoutMs = 15_000) {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const rows = await query<{c: number}>(
      `SELECT count() AS c FROM ${table} WHERE project_id = {p:UInt64}`,
      { p: projectId },
    );
    if ((rows[0]?.c ?? 0) >= expected) return;
    await new Promise(r => setTimeout(r, 500));
  }
  throw new Error(`timeout waiting for ${table} count = ${expected}`);
}
```

Wait for `events` (not `events_buffer`) because MVs read from `events`, not the buffer.

### AOV assertions

With 30 purchases at $50 and 20 purchases at $60:
- control:   aov = 50.00, total_revenue = 1500.00, orders = 30
- treatment: aov = 60.00, total_revenue = 1200.00, orders = 20

Allow ±0.01 tolerance for floating-point rounding in CH.

### Sessions assertions

Seed 50 `page_view` events per variation in the same sessions as `experiment_view`. Bounce rate = 0 (every session has a page view). Pages/session = 1 (one page view per session).

### Cleanup

Use `ALTER TABLE events DELETE WHERE project_id = {p}` after the test suite. Wrap in `afterAll`. Ignore errors if the table was already cleaned.

```ts
afterAll(async () => {
  await command(`ALTER TABLE events DELETE WHERE project_id = ${PROJECT_ID}`).catch(() => undefined);
});
```
