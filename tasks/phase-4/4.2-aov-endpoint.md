## Goal

Implement `GET /api/v1/metrics/aov` — returns average order value per variation, converted to `report_currency`, with Welch's t-test significance on every pair vs the lowest `variation_id` (treated as control).

## Context

The architecture doc specifies Welch's t-test for AOV significance. Welch's t-test requires:
- mean (AOV) per variation — available from `mv_aov_daily`
- variance of the per-order value distribution — NOT in `mv_aov_daily` (only `sum` and `count`)
- sample size (orders) per variation — available from `mv_aov_daily`

To get variance without querying raw events on every request, this task adds a CH migration (`011`) that adds `sum_sq` to a new `mv_aov_daily_v2` materialized view. `mv_aov_daily` from migration 003 is retained for backwards compatibility (dashboard prototypes may query it directly); the read API uses `mv_aov_daily_v2`.

## Acceptance criteria

- Migration `011_mv_aov_daily_sumsq.sql` creates `mv_aov_daily_v2` with columns `revenue`, `orders`, `sum_sq` (sum of value_native^2 per variation per currency per day).
- `GET /api/v1/metrics/aov?experiment_id=42&from=2026-04-01&to=2026-05-01&report_currency=USD` returns `AovSummary` (from `packages/shared-types`).
- FX conversion uses the `fx_rates` CH dictionary (see migration 008). When `currency = report_currency`, `dictGet` is skipped.
- `significance` array contains one entry per (reference, compared) pair where reference = variation with lowest `variation_id`. Pairs include all non-reference variations.
- Welch's t-test p-value is computed in TypeScript (not CH SQL).
- Default `from` = today minus 30 days, `to` = today. `report_currency` defaults to `'USD'`.
- `experiment_id` query param is required; returns `400 { error: "experiment_id required" }` when missing.
- Unit tests for `stats.ts` cover Welch's t-test with known vectors (small dataset where p can be computed by hand).
- Handler test stubs the CH query and checks response shape.
- `pnpm -r typecheck && pnpm -r test && pnpm lint` pass.

## Implementation notes

### Migration 011

```sql
-- apps/collector/db/migrations/011_mv_aov_daily_sumsq.sql
CREATE MATERIALIZED VIEW IF NOT EXISTS mv_aov_daily_v2
ENGINE = SummingMergeTree
PARTITION BY toYYYYMM(day)
ORDER BY (project_id, experiment_id, variation_id, currency, day)
SETTINGS allow_nullable_key = 1
AS
SELECT
    toDate(client_ts)               AS day,
    project_id,
    experiment_id,
    variation_id,
    currency,
    sum(value_native)               AS revenue,
    count()                         AS orders,
    sum(value_native * value_native) AS sum_sq
FROM events
WHERE event_name = 'purchase' AND is_bot = 0
GROUP BY day, project_id, experiment_id, variation_id, currency;
```

The `SummingMergeTree` aggregates `revenue`, `orders`, and `sum_sq` independently — no special treatment needed; they're all summable.

### Query (with FX conversion)

Multi-currency batches are possible (a project accepts EUR and GBP). Convert each daily row to `report_currency` via the CH dictionary before summing:

```sql
SELECT
    variation_id,
    sum(revenue *
        dictGetOrDefault('fx_rates', 'rate',
          tuple(toDateTime(toStartOfDay(day)), currency, {report_currency:String}),
          1.0)
    ) AS revenue_usd,
    sum(orders)                AS orders,
    sum(sum_sq *
        pow(dictGetOrDefault('fx_rates', 'rate',
          tuple(toDateTime(toStartOfDay(day)), currency, {report_currency:String}),
          1.0), 2)
    ) AS sum_sq_usd
FROM mv_aov_daily_v2
WHERE project_id = {project_id:UInt64}
  AND experiment_id = {experiment_id:UInt64}
  AND day BETWEEN {from:Date} AND {to:Date}
GROUP BY variation_id
```

Note: `sum_sq` in report currency = `sum(value_usd^2)` ≈ `sum(value_native^2 * rate^2)`. This is correct only when the rate is constant across orders. With daily rate granularity this is a slight approximation; acceptable for v1.

Use the Abramowitz & Stegun series approximation for the p-value rather than pulling in a stats library.

### Sample variance from aggregates

```ts
// Given: sum(x), count(x), sum(x^2)
function sampleVariance(sum: number, sumSq: number, n: number): number {
  if (n < 2) return 0;
  const mean = sum / n;
  return (sumSq - n * mean * mean) / (n - 1);
}
```

### Response shaping

```ts
// packages/shared-types AovSummary
const variations: AovMetric[] = rows.map(r => ({
  variation_id: r.variation_id,
  aov: r.revenue_usd / r.orders,
  ci_low: ...,  // Welch 95% CI: mean ± t_{df, 0.025} * sqrt(var/n)
  ci_high: ...,
  total_revenue: r.revenue_usd,
  orders: r.orders,
  sample_size: r.orders,
}));
```

The CI uses the same Welch t-distribution quantile: `aov ± t_crit * sqrt(var / n)` where `t_crit` ≈ 1.96 for large n, computed via inverse CDF. For v1, use the normal approximation (`1.96 * sqrt(var / n)`); flag in a comment if n < 30.

## Tests

`apps/collector/src/metrics/__tests__/aov.test.ts`:

- Stub `query` from `../../db/clickhouse.ts` to return two variation rows.
- Assert response matches `AovSummary` shape.
- Assert `significance` has one entry (2 variations → 1 pair).
- Test with `report_currency` absent → defaults to USD.
- Test missing `experiment_id` → 400.

`apps/collector/src/metrics/__tests__/stats.test.ts` (or inline in `stats.ts` test file):

- Pin a known vector (two samples with known t-value and p-value).
- Assert `welchTTest` is within 0.001 of the reference p-value.
- Edge: n=1 → p=1.

## Out of scope

- Bayesian significance (frequentist Welch is v1).
- Confidence intervals using bootstrap resampling (bootstrap is for RPV per task 4.3).
- Backfilling `mv_aov_daily_v2` for historical events (only new events after migration 011 runs will appear in v2; v1 dashboards therefore show accurate data only from go-live).
- Multi-experiment batching (one experiment per request).
