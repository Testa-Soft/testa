## Goal

Serve `GET /api/v1/metrics/sessions` → `SessionsSummary`: per-variation session
count, bounce rate, and pages-per-session, read from `mv_sessions_daily`.

## Acceptance criteria

- Valid `SessionsSummary`: per variation `sessions`, `bounce_rate`,
  `pages_per_session`, `sample_size = sessions`.
- `sessions = uniqExactMerge(sessions)`.
- `bounce_rate = 1 - (uniqExactMerge(sessions_with_pageview) / sessions)` —
  i.e. the fraction of sessions with no meaningful page_view. (Confirm the
  definition against `mv_sessions_daily`'s `sessions_with_pageview`; document
  the exact formula chosen.)
- `pages_per_session = countMerge(page_views) / sessions`.
- `sessions = 0` → all metrics `0`, no divide-by-zero.
- No significance block required for v1 sessions (note it; add later if PM asks).

## Implementation notes

- `mv_sessions_daily` stores Aggregating state columns — read every one with its
  `-Merge` combinator, never the raw state.
- Depends only on 4.3's `sessionsByVariation`; no stats module needed here.
- This endpoint is the natural consumer of the page_view rows added by pixel
  task 3.16 + collector task 1.8 — with `in_experiment`-scoped retention, the
  30-day experiment window is fully covered.

## Tests

- Seeded CH: sessions with/without page_views → assert `bounce_rate` and
  `pages_per_session` against hand-computed values.
- `sessions = 0` → zeros, not NaN.

## Out of scope

- Session significance testing.
- Time-on-page / scroll-depth (not in the MV; separate workstream).
