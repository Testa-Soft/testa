**Assumptions**
- Rollback to v1 is refused while any v2 experiment exists, *including soft-deleted ones*: their data is v2 and they could be restored.
- An experiment's `platform_version` is enforced as immutable at model level (`updating` throws). A copy is in the same project, so the "target project" is the source's project at copy time.
- The v2 routes bind `{experiment}` by **id**, as in the PRD (the legacy API uses `identifier`). The 409 guard runs before the controller's 403, so a guessed id from another client can learn the version. That is minor; the C3 controller could authorize in middleware if wanted.
- Settings bounds, which the PRD doesn't give: confidence 0.8–0.99, expected-loss limit (0, 0.1], MDE (0, 1). Metric ids are validated by format only `[a-z0-9_:]{1,128}`, max 50, distinct.
- v2 preset goals store `action = ''` (the column is NOT NULL). Only click, page_view and custom carry an action.
- Reporting currency has its own endpoint, `PUT /api/projects/{uuid}/reporting-currency` (ADMIN/SUPER_ADMIN, scoped to the user's client). The existing project update endpoint takes the full object and has DTO type quirks, so I left it alone. The ISO 4217 list is hardcoded because symfony/intl isn't installed.
- "Subscription dirty" is the event `App\Domain\Experimentation\Events\AnalyticsSubscriptionDirty{experimentId, reason}`. It fires for live (non-archived) v2 experiments on goal-set change, pinned-metrics change, and project currency change. Wizard-time settings don't fire it, since there is no subscription yet.
