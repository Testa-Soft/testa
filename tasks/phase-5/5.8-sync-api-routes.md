## Goal

Replace the P0 stubs in `src/sync/router.ts` with the real endpoints. **Reads never compute:** they only read `metric_subscriptions`, `metric_daily` and Redis run / query state.

## Acceptance criteria

- `PUT …/subscription`: validate (`status`, `from`, `to`, `report_currency`, `metrics` against `MetricKey`), upsert `metric_subscriptions`, enqueue at high priority when metrics changed or status → `stopped`; respond `200 {status, next_run_at}`. `DELETE` writes `status = deleted`.
- `GET …/daily-summary[?since_run_id]`: status per PRD §3.3 from run state; rows from `metric_daily` filtered on `last_ready_run_id`; `unchanged: true` with no rows when `since_run_id` matches; `not_ready` → `rows: []`; `retry_after` in body and `Retry-After` header; `quality` included.
- `POST …/queries`: validate per view; return `200 ready` with the result when cached and `refresh` is false, else enqueue and return `202 {query_id, status, retry_after}`. `GET …/queries/:id`: status, rows / result, `410 expired` after TTL.
- Errors and limits exactly as PRD §5.5 (400 codes, 404 `experiment_not_found` / `not_subscribed` / `query_not_found`, 409 `version_mismatch` via `requireV2Experiment`, 429 `too_many_queries`).
- p95 under 200 ms for a 14-day × 3-variation × 22-key response (local docker).

## Tests

- Every status transition (not_ready → queued → running → ready → running-with-old-rows → failed-with-old-rows).
- `since_run_id` unchanged path; every error code; 429 after 60 POSTs/min.
- Response bodies match the PRD §3.4–3.5 examples' shape.

- `bun test apps/collector/src/sync`
