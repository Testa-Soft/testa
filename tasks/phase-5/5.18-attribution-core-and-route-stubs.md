## Goal

One shared, tested SQL builder for "exposed visitors + attributed events" that the daily rows and every view use; plus mounted stubs and a view registry so parallel sessions never edit `index.ts` or each other's folders.

## Context

Part of PRD-006. **Parts 5–6 of the PRD win over earlier sections.** Defaults in §5.1 and decisions in §6.1 are final; don't re-ask. The sync model (PRD Part 3) replaced the synchronous report endpoint.

## Acceptance criteria

- `buildExposedVisitors({projectId, experimentId, from, to, dims})`: SQL + params for the exposed set (`uniqExactMerge(variations_seen)=1`, first exposure in [from,to] UTC, first-exposure `date`, dimension values incl. derived `screen_resolution` and `visitor_type` from `max_session_idx` + attributed events, PRD §5.4).
- `buildAttributedEvents({…, eventNames})`: events with `has(exp_ids, E)`, `is_bot = 0`, joined to the exposed set, carrying the **exposure** variation and the visitor's first-exposure `date`; global purchase dedup by `(project_id, order_id)` (earliest) applied first.
- `quality` helpers: multi-variation visitor count, variation-mismatch event count.
- **View registry** `src/analytics/views.ts`: `type ViewName = 'summary' | 'products' | 'distributions' | 'health'`; `interface ViewRunner<P, R> { validate(params): P; run(ctx, params): Promise<R> }`; `registerView(name, runner)` / `getView(name)`. Stub runners in `products/view.ts`, `distributions/view.ts`, `health/view.ts` register themselves and throw `not_implemented`. The `summary` runner is registered by P4.
- **Mounted stubs** behind the service-token middleware (`src/auth/service-token.ts`):
  - `src/sync/router.ts`: `PUT|DELETE /api/v1/experiments/:id/subscription`, `GET …/daily-summary`, `POST …/queries`, `GET …/queries/:queryId` → 501 `not_implemented` (P4 replaces).
  - `src/stats/router.ts`: `POST /api/v1/stats` → 501 (P3 replaces).
  - **After P0, only the owning session edits its folder; nobody edits `index.ts`.**
- `src/modeler/main.ts`: an entry that logs "modeler stub" and exits 0; `package.json` adds `dev:modeler` and includes it in `build` (P4 fills it).
- Shared guard `requireV2Experiment(config, experimentId)`: 404 `experiment_not_found` if absent, 409 `version_mismatch` if `platform_version` isn't `v2`.
- Remove the old 501 stub `GET /api/v1/metrics/:metric`.
- Parameterised queries only; dimension and event keys from allowlists.

## Tests

- Integration (docker CH, own database): F1 events inserted directly → exposed set = 3 / 3 visitors for 1717, v4 excluded, v9 excluded; attributed purchases match F1 (O1 once, O6 not attributed); every attributed row carries the first-exposure date.
- Registry: registering twice throws; unknown view → `unknown_view`.
