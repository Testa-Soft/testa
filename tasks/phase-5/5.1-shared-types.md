## Goal

Add every new wire field and the sync API / view / stats types so all later tasks share one contract.

## Context

Part of PRD-006 (`docs/prds/006-ecommerce-events-and-metric-modeling.md`). **Part 5 of the PRD wins over earlier sections when they disagree.** Defaults in §5.1 are decided; don't re-ask.

## Acceptance criteria

- `PixelEvent` gains `exp: [number, number, number, number][]` (expId, varId, sessionStart, sessionIdx), `items?: Item[]`, `page_type?`, `cart_id?`, `purchase_type?: 'initial' | 'upsell'`, `parent_order_id?`, `utm_term?`, `utm_content?`, `screen_w`, `screen_h`, `visit_number`, `entry_referrer?`, `entry_url?`, `entry_utm_source|medium|campaign|term|content?`, `click_id_type?`.
- `EnrichedEvent` gains `os_name`, `os_version`, `browser_name`, `browser_version`, `referrer_domain`, `channel`.
- `ReservedEventName` adds `begin_checkout`, `add_shipping_info`, `add_payment_info`, `generate_lead`, `sign_up`, `view_item`, `view_item_list`, `remove_from_cart`, `view_cart`; `checkout_start` documented as a deprecated alias; JSDoc warns `lead_generated` ≠ `generate_lead`.
- `Item` interface exactly as PRD §1.6.
- `sync.ts` (PRD Part 3):
  - `MetricKey`: the 22 daily keys of PRD §2.3 (`purchase`, `upsell`, `revenue`, `add_to_cart`, `begin_checkout`, `add_shipping_info`, `add_payment_info`, `generate_lead`, `sign_up`, `page_view`, `units`, `units_added`, `units_bought_from_cart`, `coupon`, `lead`, `lead_purchase`, `repeat_purchase`, `cart_purchase`, `checkout_purchase`, `session`) + template literals `event:${string}` / `goal:${number}`.
  - `DailyRow` (`date`, `variation_id`, `metric_key`, `visitors`, `converted`, `count`, `sum`, `sum_sq`, `sum_sq_visitor`) and `DimensionRow` (+ `dimension`, `dimension_value`). `DimensionKey` union (PRD §3.6).
  - `SyncStatus = 'ready' | 'queued' | 'running' | 'not_ready' | 'failed'`.
  - `SubscriptionRequest` / `SubscriptionResponse`, `DailySummaryResponse` (incl. `unchanged?: true`, `quality`), `QueryRequest` (`view: 'summary' | 'products' | 'distributions' | 'health'` + per-view params), `QueryAccepted`, `QueryResponse` (`rows` for summary, `result` for the other views), `WebhookPayload` (`summary-ready` | `query-ready`), `SyncErrorCode` union (PRD §5.5).
- `report.ts` (views + stats): `ProductsParams/Result`, `DistributionsParams/Result`, `HealthResult`, `QualityBlock`, `StatsRequest` / `StatsResponse` for `POST /api/v1/stats` (summed inputs per variation per metric → `VariationStats`), and **`EVENT_PARAM_SPEC`** (required params per event, PRD §6.5). The old flat-report types (`ReportRequest`/`ReportResponse`/`GroupByKey`) are **not** created.
- Example payloads exist in `docs/reference/samples/{demo,f1}/modeled/` (`daily_summary*.json` = summary rows; `products`, `distributions`, `health` = view results), generated by `docs/reference/samples/generate.py`, the reference oracle. The types must match them (envelope fields like `status`/`run_id` are added by the API and absent from the samples). Add a `bun` check that validates every sample file against the types; if a sample and the PRD disagree, log it under Questions for human.
- `ProjectConfig.experiments[].platform_version?: 'v1' | 'v2'` (absent = v1) + `docs/reference/project-config-shape.md` updated (mailbox R1).
- `metric-summary.ts` is left untouched (crobot may import it) and marked `@deprecated`.
