## Goal

One command proves PRD-006 end to end: `pnpm prd006:validate` brings up the
local stack, loads fixtures through the real ingest path, runs every
validation flow in `docs/prds/006-validation.md`, and writes a pass/fail
report.

## Context

Part of PRD-006. Built in session P5 (fixtures, oracle, flows, `--dry-run`). The full run happens
in P6 after all packages merge, giving one human test pass at the end. **The expected values in
`006-validation.md` are the spec. Never change them to make a flow pass.**

## Acceptance criteria

- **Oracle = daily rows.** `oracle.ts` ports `docs/reference/samples/generate.py` (`summary_values`, `daily_summary`) to TypeScript and emits the PRD §2.3 rows; flows compare `metric_daily` / API rows to it and derive the 006-validation.md ratios with the §2.3 formulas. `bun test scripts/e2e/prd006` must reproduce `docs/reference/samples/f1/modeled/daily_summary.json` exactly.

- `pnpm prd006:validate [--only F1|V4|…] [--keep-up]`:
  1. `docker compose up -d redis clickhouse`, waits for health
  2. `migrate`
  3. starts the collector server + consumer + **modeler** (`MODELER_INTERVAL_SEC=5`) as child processes with test env
     (service token, ingest secret, webhook URL pointing at a local receiver)
  4. seeds FX (USD→EUR 0.9, GBP→EUR 1.15) and the project configs for
     experiments 1717 / 1802
  5. ingests the fixtures (HMAC-signed, batched by 500)
  6. waits for the buffer flush
  7. subscribes the fixture experiments through the sync API, waits for `status: ready`, then runs V1–V8, V10, V12–V17, plus V9 via `pnpm --filter @testa-platform/pixel test:e2e -g prd006`, plus V11
  8. writes `docs/prds/006-validation-report.md`
  9. tears down unless `--keep-up`
  10. exits non-zero on any failure
- `--dry-run` builds the fixtures, runs the oracle and prints the plan without starting anything.
- **F1** is encoded exactly as the table in `006-validation.md`. Its expected
  values are **literal constants** in `f1.ts`, copied from the doc, never
  computed.
- **F2:** a seeded generator (`seed = 1717`) with the distributions listed in
  the doc. `oracle.ts` computes expected daily rows from in-memory events in
  plain TypeScript. It must **not** import anything from
  `apps/collector/src/modeler`, `src/sync` or any view folder (it must stay independent).
- **F3:** golden counts exactly as specified.
- Report format: one table per flow, with check, expected, actual and ✅/❌,
  plus timings.
- CI: a `prd006-validate` job (ClickHouse + Redis services, like the
  collector job) running `pnpm prd006:validate --only V1,V2,V3,V5,V7,V8`
  (fast subset).

## Implementation notes

- Reuse the HMAC signing from `apps/collector/scripts/smoke-ingest.ts`.
  Events are `EnrichedEvent`s (edge enrichment is covered by edge unit
  tests and V9).
- Buffer flush: poll `SELECT count() FROM events WHERE project_id IN (…)`
  until it equals the number of ingested events (60 s timeout). Don't use
  `OPTIMIZE`.
- Use a dedicated project id range (≥ 900000) so local dev data never
  collides.

## Tests

- `oracle.test.ts`: the oracle reproduces F1's literal expected values when fed
  F1's events. This cross-checks the oracle against the hand-computed numbers
  before it's trusted on F2.
