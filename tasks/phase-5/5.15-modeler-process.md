## Goal

The background process that keeps every subscribed experiment's daily rows fresh and runs on-demand queries, so no HTTP request ever waits on modeling (runs take 1–2 min on big experiments).

## Acceptance criteria

- **Scheduler** (every 15 min, configurable): reads `metric_subscriptions FINAL`; enqueues `running` subscriptions with events newer than the last run's `data_through`; forces a run when the last finished run is > 24 h old; `stopped` subscriptions get one final run (`is_final = 1`) and are not refreshed again.
- **Queue:** Redis sorted set `modeler:queue`, score = priority then enqueue time; an experiment / query is in the queue at most once; per-experiment lock `SET NX` TTL 10 min.
- **Workers:** `MODELER_CONCURRENCY` (default 4) loops; ClickHouse `max_execution_time` 300 s.
- **Run:** `computeDailyRows` for the full `[from, to ?? today]` → insert into `metric_daily` with a new `run_id` (ULID) → mark ready. Readers never see a partial run.
- **Run state** Redis hash `modeler:run:{experimentId}`: `status`, `run_id`, `last_ready_run_id`, `computed_at`, `data_through`, `queued_at`, `started_at`, `error`, `attempt`.
- **Retries:** 3 (30 s, 2 min, 5 min), then `failed`; last good run stays readable.
- **`retry_after`** helper: from queue position × recent average run time (min 10 s, max 600 s), used by 5.8.
- **Query jobs:** `query_id` = sha256 of the canonical body minus `refresh`; runs the registered view; result stored in Redis `modeler:query:{id}` TTL 3600 s; higher priority than refreshes.
- **Webhook** (when `CROBOT_WEBHOOK_URL` is set): `summary-ready` / `query-ready` bodies per PRD §3.5, headers `X-Testa-Timestamp` + `X-Testa-Signature: sha256=HMAC(secret, ts + "." + body)`; retries 10 s, 1 min, 5 min, then dropped.
- Config env: `MODELER_CONCURRENCY`, `MODELER_INTERVAL_SEC`, `CROBOT_WEBHOOK_URL`, `CROBOT_WEBHOOK_SECRET`. Redis key prefix per session in tests (`prd006:s4:`).

## Tests

- F1 subscription → one run → `metric_daily` rows equal the F1 golden; second tick without new events enqueues nothing; a new event → new `run_id`.
- Lock: two workers never run the same experiment.
- Failure path: injected error ×3 → `failed`, previous run still served.
- Webhook signature verifies with the shared secret; retry on 500.
- Query dedup: same body twice → one job.
