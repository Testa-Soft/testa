## Goal

Persist every new field, and write one `event_items` row per item.

## Context

Part of PRD-006 (`docs/prds/006-ecommerce-events-and-metric-modeling.md`). **Part 5 of the PRD wins over earlier sections when they disagree.** Defaults in §5.1 are decided; don't re-ask.

## Acceptance criteria

- `exp` → `exp_ids` / `exp_var_ids` / `exp_session_starts` / `exp_session_idx` parallel arrays.
- All new scalar columns are mapped, with defaults when absent.
- `event_items` rows inserted in the same batch cycle as the events, carrying event_id, order_id, purchase_type and exp_ids.
- Missing `product_id` defaults to `item_id`.

## Tests

- row-mapper unit tests for every new field.
- Consumer test: a purchase with 2 items → 1 events row + 2 event_items rows.

- `pnpm --filter @testa-platform/collector test`
- Run `scripts/smoke-ingest.ts` with a PRD-006 purchase (2 items): check 1 `events` + 2 `event_items` rows
- Then G3: `pnpm -r typecheck && pnpm -r test && pnpm lint` (see `LOOP.md`)
