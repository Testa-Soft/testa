## Goal

One function that turns raw events into the additive daily rows of PRD §2.2–2.3. The modeler (5.15) stores its output for core rows; the `summary` view runs it with a dimension for on-demand queries.

## Context

Part of PRD-006. **Parts 5–6 win.** No derived metric is ever computed here: rows only carry `visitors`, `converted`, `count`, `sum`, `sum_sq`, `sum_sq_visitor`. Crobot sums and divides.

## Acceptance criteria

- `computeDailyRows({projectId, experimentId, from, to, reportCurrency, metrics, dimension?, capOutliers?}) → { rows: DailyRow[] | DimensionRow[], quality }`.
- Uses `buildExposedVisitors` / `buildAttributedEvents` (5.18). One pass over events per call: per-visitor `-If` aggregates, then grouped by `date × variation_id (× dimension_value)`.
- Every one of the 22 keys exactly as PRD §2.3 (`converted` / `count` / `sum` semantics per key), plus `event:<name>` and `goal:<id>` (`goal_id` column on `conversion` events).
- `visitors` repeated on every key's row; a key with no activity still emits a row with zeros (crobot needs the denominator).
- **Money:** each order converted to `reportCurrency` at the **previous UTC day's** rate via the `fx_rates` dictionary (5.19 provides the fallback); `sum_sq` per order, `sum_sq_visitor` per visitor.
- **Session seconds** per PRD §5.4.
- **Dimensions:** top 10 values by visitors across all variations + `(other)`; `visitor_type` per PRD §1.3a (the visitor's max `session_idx` ≥ 2 → `returning`, all their events follow).
- `capOutliers`: p99 of initial-order values (pooled) caps per-order values in `sum`/`sum_sq` for revenue keys.
- Registers the `summary` view runner (`src/modeler/summary-view.ts`) in the view registry from 5.18.

## Tests

- **F1 golden:** rows equal `docs/reference/samples/f1/modeled/daily_summary.json` exactly (order-insensitive), F1 events inserted straight into `events` / `event_items`.
- Summing the rows reproduces F1's CR / AOV / RPV from `docs/prds/006-validation.md`.
- Dimension rows for each value sum to the core row (visitors, converted, count, sum).
- A visitor who returns (session_idx 2) moves to `returning` with all earlier events; totals unchanged.
- FX: a USD order converts at the previous day's rate.
- **Fixture FX:** the oracle uses constant rates (`generate.py` `FX`: 1 USD = 0.9 EUR, 1 GBP = 1.15 EUR). Seed `fx_rates_history` with those rates for every fixture day **and the day before**, so the golden matches regardless of the previous-day rule.
