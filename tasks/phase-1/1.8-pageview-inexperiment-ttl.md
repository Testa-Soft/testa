## Goal

Store an `in_experiment` flag on every event and give `page_view` rows cheap,
differential retention: non-experiment page_views (the highest-volume,
lowest-value rows) expire in 1 day, experiment-associated page_views survive
30 days, and everything else keeps the existing 13-month TTL. This makes it
affordable to emit page_view for all human traffic (see 3.16) while keeping
ClickHouse small.

## Context

The `events` table (task 1.1) currently has a single blanket TTL of
13 months and no `in_experiment` column. The pixel (task 3.16) will stamp
`in_experiment` on each event; this task adds the column, wires it through
the wire types + row-mapper, and replaces the TTL.

**Prospective-only** by design: ClickHouse cannot raise a row's TTL after
write (TTL derives from the row's own columns; no cross-row lookup). So
page_views before a visitor's first exposure stay `in_experiment=0` and are
reaped at 1 day — accepted for MVP (see PRD-002 "Accepted limitations").

## Acceptance criteria

- New column `in_experiment UInt8 DEFAULT 0` on the events table.
- `in_experiment` added to `PixelEvent`/`EnrichedEvent` wire types and mapped
  through `rowFromEvent` (`EventsRow`).
- TTL replaced with an **event_name-scoped** rule (must NOT reap conversions):

  ```sql
  TTL toDateTime(client_ts) + INTERVAL 1 DAY   DELETE
        WHERE event_name = 'page_view' AND in_experiment = 0,
      toDateTime(client_ts) + INTERVAL 30 DAY  DELETE
        WHERE event_name = 'page_view' AND in_experiment = 1,
      toDateTime(client_ts) + INTERVAL 13 MONTH DELETE
  ```

- Migration is idempotent / re-runnable via the existing migrate runner
  (task 1.2), and registered in the `_migrations` tracker.
- **No `page_path` column** and **no `SAMPLE BY` / no reorder** of the events
  table (page-path normalization + sampling strategy live in crobot; the
  `event_name`-first sort key already makes `WHERE event_name='page_view'` a
  prefix range scan).

## Implementation notes

- `ALTER TABLE events MODIFY TTL ...` changes retention going forward;
  confirm the migrate runner applies it and that the Buffer table
  (`events_buffer`, task 1.1/002) inherits/forwards correctly (Buffer has no
  TTL of its own — it flushes to `events`, which owns the TTL).
- The MVs (`003`–`007`) read `FROM events`; none filter on `in_experiment`,
  so this column is additive and does not change existing rollups.

## Tests

- `rowFromEvent` carries `in_experiment` from an `EnrichedEvent` into the
  `EventsRow` (unit).
- TTL reaping (integration): insert a `purchase`, an `in_experiment=1`
  page_view, and an `in_experiment=0` page_view with a `client_ts` older than
  1 day; force the TTL merge (`OPTIMIZE TABLE events FINAL` / materialize
  ttl); assert only the `in_experiment=0` page_view is gone and the other two
  survive. Prior art: collector CH integration tests (task 1.7 / the
  `__tests__/integration.test.ts` scaffold).
